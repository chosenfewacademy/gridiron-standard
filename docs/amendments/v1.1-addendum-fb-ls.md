# v1.1 Addendum Note — FB and LS buckets (PROPOSED, NOT ENACTED)

Status: PROPOSED — requires explicit commissioner enactment. Flagged to the commissioner on 2026-11-01.
This note does not edit Architecture/Methodology v1.0.0 text or the enacted v1.1 amendment in AGENTS.md.

## Why an addendum is needed
Architecture v1.0.0 defines a fixed 20-position sequence (config/position-sequence.json, `architecture_version` 1.0.0)
and AGENTS.md A3 attaches rating inputs to "every exact bucket". Adding fullback (FB) and long snapper (LS) as
exact buckets extends that architecture, so it cannot be done silently.

## What exists now (inputs only)
- config/position-metrics.json: `FB` (order 21) and `LS` (order 22), `current_status: ADDENDUM_PROPOSED`.
- docs/positions/FB.md, docs/positions/LS.md; config/positions/FB.md, config/positions/LS.md (architecture placeholders).
- data/candidate-pools/FB.proposed.json, LS.proposed.json (+ approved copies FB.json, LS.json via `npm run pool:approve`).

## What is deliberately NOT changed
- config/position-sequence.json (still the 20 v1.0 buckets), state/project-state.json positions, state/locks.json,
  router position regexes, locked baselines, cards and audit history.
- The stage engine therefore never schedules FB/LS work until this addendum is enacted.

## Proposed enactment (needs commissioner approval)
1. Placement in the sequence is the commissioner's call; default proposal: append `FB`, `LS` after `P` so no
   in-flight position order changes.
2. Add `FB: PENDING`, `LS: PENDING` to state via the commissioner state path (not a hand edit).
3. Add FB/LS to router bucket regexes and the position mapper's exact buckets.
4. Record the change in ARCHITECTURE_CHANGELOG.md as an Architecture 1.1.x addendum.
